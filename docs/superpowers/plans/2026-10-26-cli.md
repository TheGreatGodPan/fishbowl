# Command-Line App Implementation Plan (Stage 5)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One installable `fishbowl` command with subcommands, including `analyze` (every report, the deck read once), plus README install instructions verified on a fresh clone.

**Architecture:** `src/fishbowl/cli.py` holds a `typer.Typer` app. The simple subcommands wrap the existing `main(argv=[...])` functions. For `analyze`, each report module gains `report(deck, lookup, write, ...) -> int`, and its `main` becomes a thin wrapper around it. The `pyproject.toml` script points at `fishbowl.cli:app`.

**Tech Stack:** Python 3.12, **typer (new dependency)**, pytest with `typer.testing.CliRunner`.

**Spec:** `docs/superpowers/specs/2026-10-26-cli-design.md`

## Global Constraints

- `uv add typer` is the only new dependency.
- `[project.scripts]` becomes `fishbowl = "fishbowl.cli:app"`. Leave `fishbowl/__init__.py`'s `main` and `hello.py` alone.
- **Subcommands:**
  - `refresh`
  - `check DECK`
  - `lands DECK`, `mulligan DECK`, `groups DECK`, `curve DECK`
  - `charts DECK`
  - `analyze DECK [--charts]`
  
  `DECK` is a `Path` argument. Every subcommand exits with the code its work returns.
- **analyze section headings, in order:**
  - `== Deck check ==`
  - `== Land odds ==`
  - `== Mulligans ==`
  - `== Card groups ==`
  - `== Commander on curve ==`
  - `== Charts ==` (only with `--charts`)
  
  Each heading is preceded by a blank line. Every section runs. The exit code is 0 only if every section returned 0.
- **Missing-database hint text** is now `"  uv run fishbowl refresh"`, in `deck/parser.py` `find_deck_file` and in `data/database.py`.
- The `python -m fishbowl...` commands keep working, with the same output as today.
- Tests never touch the real `data/` or `charts/`. They use the `card_db` fixture and `tmp_path`.
- Agents never run `git add`/`commit`/`push`. Ian commits after each task.
- Every touched `.py` file passes `ruff format`, `ruff check` and `~/.local/bin/basedpyright.exe --level error -p C:/Users/iwsch/.claude/hooks/basedpyright-default.json <file>`.

## Review Focus

1. **A deck with no commander line in analyze:** asks exactly once. (Task 2 `test_analyze_asks_once`.)
2. **The database is missing:** every deck subcommand prints the new `uv run fishbowl refresh` hint and exits 1, without a traceback. (Task 1 `test_missing_db_hint`.)
3. **A file that doesn't exist:** a clear message and exit 1. Typer can check this with `exists=True`, or the wrapped `main` can do it; either way it's tested. (Task 1 `test_missing_deck_file`.)
4. **A tiny deck in analyze:** the sections that can't run print their "Only N cards…" line, the rest still print, and the exit code is 1. (Task 2 `test_analyze_tiny_deck`.)
5. **Following the README on a clean machine:** it actually works. (Task 3's fresh-clone run.)

### Task 2: `report` functions and `analyze`

**Files:**
- Modify: `src/fishbowl/deck/parser.py`, `src/fishbowl/stats/{lands,mulligan,groups,curve,charts}.py`, `src/fishbowl/cli.py`
- Test: `tests/test_cli.py`, plus one `test_report_matches_main` in each of `tests/deck/test_parser_main.py`, `tests/stats/test_lands_main.py`, `test_mulligan_main.py`, `test_groups_main.py`, `test_curve_main.py` and `test_charts_main.py`

**Interfaces:**
- Produces, in each module:
  - `deck.parser.report(deck: ParsedDeck, lookup: CardLookup, write: Callable[[str], object]) -> int`. It's the current body of `main` from `validate` onward.
  - `stats.lands.report(deck, lookup, write, trials: int = TRIALS) -> int`, and the same signature for `mulligan`, `groups` and `curve`. Each is the current body of `main` after `read_deck`.
  - `stats.charts.report(deck, lookup, write, trials: int = TRIALS, out_dir: Path = Path("charts"), stem: str = "deck") -> int`. `stem` is the deck file's stem.
  - Each `main`: `find_deck_file` → `with CardLookup(db_path) as lookup:` → `deck = read_deck(...)` → `return report(deck, lookup, write, ...)`. `report` runs *inside* the `with` block, because `groups` and `curve` need the lookup.
  - `cli.analyze(deck: Path, charts: bool = False)`: it runs the database and file checks through `find_deck_file`, with usage `"Usage: fishbowl analyze <decklist.txt>"`, then opens one lookup and reads the deck once. It writes each heading and calls the reports in order: check, lands, mulligan, groups, curve, and then charts (`out_dir=CHARTS_DIR`, `stem=deck.stem`) if `--charts`. Finally it exits `0 if all(code == 0 …) else 1`.

- [ ] **Step 1: Write the failing tests.**
  - `test_report_matches_main` in each module's test file: parse the standard Goreclaw test deck with `parse_deck` and `CardLookup(card_db)`, call `report(...)` collecting lines, and compare with `main`'s output for the same file. The lines must be equal once `main`'s commander prompts are left out; the Goreclaw deck has a `Commander:` line, so there are none.
  - In `tests/test_cli.py`:
    - `test_analyze_headings`: exit 0 for the standard deck (it's a legal deck, so check returns 0 — confirm, and if the test DB makes it illegal, assert the code that check's own `main` gives). The five headings appear in order, and there is no Charts heading.
    - `test_analyze_asks_once`: the deck has no `Commander:` line (`1 Goreclaw…`, `33 Forest`, `66 Sol Ring`). Answer with `input="1\n"` (`analyze` reads with `input`, so typer's runner provides it), and check that the prompt text "Which card is your commander?" appears exactly once.
    - `test_analyze_charts`: `--charts` adds the `== Charts ==` heading, and the PNGs land in the patched `CHARTS_DIR`.
    - `test_analyze_tiny_deck`: `Commander: Goreclaw`, `1 Goreclaw`, `4 Forest`, `4 Sol Ring`. Exit 1, all five headings print, and `"Only 8 cards in the library"` appears.

- [ ] **Step 3: Implement the split in each module, then `analyze`.** Change only the code layout. Output must stay byte-for-byte the same, which the existing `*_main` tests guard.
